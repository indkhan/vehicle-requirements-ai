# Frontend scope

The original frontend boundary was approved on 10 October 2026 in [frontend_plan.md](../../frontend_plan.md), with [plan.md](../../plan.md) defining the shared integration contract. The [portfolio implementation plan](../PORTFOLIO_IMPLEMENTATION_PLAN.md), accepted for implementation on 14 October 2026, now extends that boundary in later phases. Phase 0 establishes the release baseline, supported [flagship scenario](../portfolio/FLAGSHIP_SCENARIO.md), and [evaluation rubric](../portfolio/EVALUATION_RUBRIC.md); it does not add the prepared example, project library, comparison UI, or evidence lifecycle yet. Do not treat older pitch briefs or previous UI implementations as additional scope.

Keep vehicle selection, uploads, participation mode, initial Deep Dive selection, Create run, baseline car navigation, tags, typed graph, finding/evidence panels, scoped alternatives, proposal editing, explicit Reimagine, numbered change explanations, history and version-bound export interactions within one workspace. Counts, scores and research come from the application API boundary. Unsupported assets and rendering capabilities must remain explicit.

Removed: separate Overview and Compare destinations, period/market comparison modes and baseline-period controls, executive KPI summaries and trends, pitch analysis updates, presentation/print controls, prepared-question research controls, mandatory sample-review steps, browser-owned approval/history state, local requirement scoring, and CSV reconstruction from partially loaded UI state. Obsolete pitch planning documents were removed as well.

Deep Dive evidence stays attached to the current finding. It does not authorize a general competitor dashboard. Regional evidence and variant cohort grouping remain in scope. The portfolio roadmap later adds regional evidence review inside this workspace, with authoritative scoped counts and comparability limits; it does not add a general market-comparison destination. Manual revised-evidence review through linked child runs is planned for Phase 4. Scheduled imports, connectors and continuous monitoring remain optional later work in [backlog.md](../../backlog.md).

Current main uses the application API by default and includes a local seeded-development-access shortcut in `FrontendApp.tsx`; explicit mock and HTTP harness modes remain available. The shortcut is not a public hosted example or production sign-in design. The application includes connected analysis/review/export and configured geometry-worker paths, with capability and integration limits documented in [frontend/README.md](../../frontend/README.md) and the [root setup](../../README.md). Preserve current graph, geometry and viewer behavior when extending the workshop. Future additions must map to the portfolio roadmap, and acceptance claims must distinguish synthetic contract checks, recorded examples, fresh live checks and historical verification.

Later portfolio phases add a prepared public example, visible priority factors and a consolidated decision sheet, persistent projects and historical comparison, policy scenarios, and new-evidence reconsideration. Keep the established neutral off-white/charcoal visual style and API-authoritative data. Browser-owned approvals/history, invented historical counts, unsupported assets and locally reconstructed authoritative scores remain excluded. Phase 0 documentation does not establish implementation or release readiness for these additions.
